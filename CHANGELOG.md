# Changelog

All notable changes to Project Forward will be documented here.

The format is loosely based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project follows [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [1.0.0] — 2026-04-28

Initial public release.

### Added
- Core SKILL.md with the Project Forward method (start at the end, three-problem model, cadence beats heroics, write the message before you need it)
- Conversational pacing discipline — ask one question at a time
- "Challenge before solving" rigor discipline with six things to test before solving (framing, omissions, assumptions, success criteria, ignored trade-offs, user's own contribution)
- "When to skip the challenge" exception, including default to producing the artifact when the user signals time pressure
- "When to decline" subsection — firm-but-helpful refusal pattern for requests involving deception, regulatory evasion, manipulation, or knowingly false documentation
- "User reviews before sending" instruction — every artifact is a draft, the user is the approver
- Version self-identification capability — skill knows its own version when asked
- `templates-guide.md` reference for routing logic and format decisions
- `marketing-program-mgmt.md` reference for marketing PM repositioning
- 13 templates: project charter, stakeholder map, RAID log, decision log, pre-mortem, kickoff agenda, weekly status, scope-change memo, escalation memo, vendor RFP scorecard, first-30-days checklist, marketing campaign brief, resource/capacity plan
- Honesty-check sections in charter, weekly status, and first-30-days templates
- Plaintext bundle (`project-forward.txt`) for mobile reading
- README with "What this is and isn't" scope disclaimer for high-stakes domains
